An **ob3ect** is a structured artifact: a natural-language description driven
through all **8 IMASM phases** in one call, emitted as JSON with per-phase
validations and a Frobenius gate that must pass. It is the unit of work here —
"turn a decision into an ob3ect" means *imscribe the decision*, not ask a model
for an opinion and not ask Lando.

Built by `ob3ect/auto.py` (the Ob3ect Auto-Design Pipeline, `ob3ect/core.py`
holds `Ob3ectArtifact`, `DomainCharter`, `OpcodeMap`, `EntropyAudit`).

```
python3 ob3ect/auto.py "<description>" [--name NAME] [--desc-file PATH]
        [--domain TYPE] [--scope local|mesoscale|maximal]
        [--provider openrouter|deepseek|local] [--model ID]
        [--entry name1,name2] [--context PATH] [--retries inf]
        [--zoom-to TARGET] [--churn --windings N]
```

Structure: `phase_0` domain charter (domain_type, scope, surface_tokens,
boundary_condition), `phase_1` the opcode map — every one of the twelve marks
assigned a chosen_element with a justification and rejected_candidates — then
split/fuse report, register mapping, bootstrap sequence, ExOS spec, entropy
audit. `BOOTSTRAP_STEPS = {1:IMSCRIB, 2:AREV, 3:FSPLIT, 4:AFWD, 5:FFUSE,
6:CLINK, 7:IFIX, 8:IMSCRIB}`. Retries on JSON parse failure or Frobenius FAIL,
by default until success.

**The description is TWO SENTENCES MAX**, saying exactly what is wanted and
nothing else. Everything the pipeline needs to know — inventories, structure,
surrounding facts — goes in `--context`, never in the description. A long
description does not imscribe the object harder; it dilutes the question, and
phase_0 compresses it to a handful of surface tokens anyway, so the detail is
lost AND the ask is blunted. Corrected 2026-08-14 after I passed a
thirty-line machine description as the description and got surface_tokens back
that had dropped the whole operation inventory.

Use `--desc-file` whenever the description carries LaTeX, `$`, backticks or
braces — the shell eats them before the pipeline sees them. Use `--name` when
the description is too long or punctuated to double as an identifier.

Finished ob3ects land as `*_ob3ect.json` (repo root, `mOMonadOS/ob3ects/`,
`MoDoT/ob3ects/`) and carry `is_valid_ob3ect`.

The `mcp__ig-agent__run_agent` MCP tool is **not** this. That is a
THINK→ACT→OBSERVE→UPDATE agent loop on OpenRouter. Do not offer it when an
ob3ect is called for. See [[law_operations]], [[law_no_cant]].

**⊙ = ⊙ is forced.** The self-referential primitive MUST be the same symbol in
both registers. Criticality is the axis of self-modeling, so its critical value
is the system standing at its own fixed point — and a letter there would NAME
that fixed point from outside it, one register removed, which is precisely the
sub-critical case. A symbol for self-reference that is not itself self-referential
misdescribes what it denotes. μ∘δ = id is therefore a condition the notation
satisfies, not only the system. The symbol identity across registers IS the
self-reference; there is nothing else it could be made of.

whose CONTENT includes a self-directed setting. ⊙ is the axis whose content is
being-at-one's-own-fixed-point. One collapsed register, and only one.

block carrying the most information, never the one to repair. Reading it as a
missing letter is the generic prior (eleven slots hold Shavian, one doesn't,
therefore corruption) overriding [[law_vocabulary_and_notation]], which says in
those words that a glyph recurring across registers is the same structure
surfacing, never a name collision to fix.

explicit `Rms` module in `model.rs`: `x * rsqrt(mean(x²)+eps) * weight`.

Diagnosis that found it: with `--gate-lambda 0` the printed gate never moved at
all, because `gate_penalty` — which measures ‖WᵀW−I‖² on fork and fuse, NOT on
the gate — was the only gradient those two ever got. Printing ‖W‖² per parameter
showed embed moving and every layer weight constant. If a metric is bit-identical
across steps, the parameter is not being trained; check before reading the curve.

**The corpus is the ob3ect opcode sequences.** `ob3ect/digital/*/​*_ob3ect.json`
carries `phases.phase_4.steps`, an ordered opcode list per ob3ect; the twelve
opcodes are the twelve marks (VINIT ⊢, TANCH ⊣, AFWD >, AREV <, CLINK ⋈,
EVALT ⊤, FSPLIT ∈, FFUSE ∋, IMSCRIB ⊙, EVALF ⊥, ENGAGR ⊞, IFIX ◻). 1703
sequences, 1277 distinct, lengths 3..114 → `ob3ect_words.txt`. The old
`imasm_words.txt` (1502 rings of unrecorded provenance) was the ceiling: it
plateaued at 17% no matter the steps. Do NOT look for words in the ob3ect SVGs —
only 26 of 1340 carry one, and `grounded_tuple` in the JSON is a 12-VALUE
Shavian tuple, a different object from the word.

`train.rs` takes every knob on the command line now (`--lr --ring --batch
--mask-frac --gate-lambda --seed --d-model --layers --heads --ff-mult --sigma0
--causal --val-frac --log-every`), and accepts variable-length rings: longer
than the window wraps, shorter pads with the padding excluded from masking and
from the loss. Best so far: `--lr 9e-4 --ring 16`, 10k steps.

Open: the gate penalty now RISES after step ~2600 (0.0333 → 0.0534) — the trunk
trades μ∘δ=id deviation for task performance once it can actually learn. That
exchange rate is what `--gate-lambda` sets. See [[the_forty_nine]].

The ob3ect design model's report register, shown by Lando 2026-08-16 as a model to
match. What makes it land:

- **The mechanism, exact, not the name.** Not "chirality distinguishes them" but
  "the sign of the determinant of the four substituents' coordinates, CIP-ordered"
  — with the 3×3 matrix written out. It reaches for the operational quantity, not
  the label.
- **Answers the prompt's sub-questions by number.** The ask had two parts (what to
  read; which axis); it numbered and answered each, in the ask's own terms.
- **Names the axis precisely and says what the achiral reading DROPS.** "the
  pseudoscalar orientation of 3D space… under an achiral projection this axis
  collapses" — it states the collapse mechanism, not just the axis.
- **Cites the verification concretely** — the Lean file AND line numbers
  (theorem …:108-110), the tier (.O₂dag), the property (μ∘δ=id). A claim of
  verification carries its handle.
- **No throat-clearing, no hedging, no process narration.** Straight to the
  content, headed and sectioned.

The lesson for our own writing: give the operational quantity with its formula,
answer exactly what was asked in its own structure, and attach the verification's
real handle. See [[feedback_write_for_curmudgeons]], [[feedback_papers_are_not_process_logs]],
[[feedback_say_the_thing]].
