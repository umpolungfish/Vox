`~/imsgct/ig-docs` holds **3311 documents across 892 directories** (`INDEX.md` is
generated by `build.py` and lists them all). Reasoning about the Grammar from
whatever happens to be in context is reasoning from a sliver, and it produces the
characteristic error: treating a routine result as a novel finding, and asking
for corroboration on something the corpus settled long ago.

**Read first, before writing or judging a word:**

- `IMSCRIBERS_GUIDE_TO_IMASM.md` — the primer, ~600 lines. The alphabet, how a
  word becomes a graph, the ancestry pairing rule, the close condition, the four
  verdicts and their sub-readings, the register and gates, the composition law,
  the op-opcode level, the 49 types. It states its own authority rule: where the
  guide and a live tool disagree, the tool is right.
- `NECESSITY_OF_THE_GRAMMAR.md` — the formal argument, with §9 grading exactly
  what is and is not carried.
- `GRAMMAR_PRIMACY_EXPLAINER.md` — the same argument in operating order, with the
  verification instruments.

**Then by subject:** `OVMs/` (the 24-cell taxonomy, the master mathematics, the
per-cell derivations, and the `decompose` CLI), `erdos*/`, `manuscripts*/`,
`physics/`, `WINDING/`, `discoveries/`, `critiques/`.

**Two things the guide changes about how to read the instruments** and both are
easy to get wrong from outside it: the 49 types are themselves IMASM programs
(`imasm types`, `imasm expand <type>` reconstructs each as a graph), and the
structural verbs run inside the agent loop via `TOOL: <verb> <args>`, not from a
shell — `./ask` alone routes the whole line to the model as a question.

**Why:** it is easy to spend a session deriving something the corpus already
states, or to publish a reading the primer would have refused in a sentence.

**How to apply:** before operating on words, read the primer. Before calling a
result new, look for it. `INDEX.md` and `command grep` over ig-docs are the two
moves, and `command grep` because bare grep honours .gitignore in this shell.
