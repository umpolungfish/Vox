Write the lift once, and make an instruction set a table

Every lane carried its own copy of the same loop: open with VINIT, then per
step emit a merge where flow joins and the glyph the step lifts to. EVM, WASM,
CPython and x86 each wrote it out again, and each wrote its opcode judgements
as match arms buried in the reader that parsed the container. Four copies of one
law is four chances for them to disagree, and the loop is not the part that
differs between instruction sets.

Two things do differ, and they separate cleanly. A container has to be parsed
into steps, which is irreducibly per-format. And each step has to be judged into
the twelve, which is a table — data, not code. src/lift.rs now holds the loop
and the table type; the readers keep only the parsing.

EVM, WASM and CPython are now const tables of ordered rules, exact or by stem,
first hit wins, so a table reads as the if-else chain it replaces and a step no
rule names lifts to nothing. x86 hands the same loop a closure instead, because
its judgement reads operands as well as the mnemonic: a call through a register
is not the call to a label. That is a richer judgement, not a different law.

Merges stay with the readers, because the evidence for them is format-shaped —
a predecessor count over jump targets where an instruction set addresses, a
control stack where it nests, as WASM does. Where the evidence lives is
per-format; what it means is not, and the loop only ever asked whether flow
joins here.

The genetic lane stays out. A transcript is a linear read with one terminal and
no branching, so it has no merges to place; putting it through a control-flow
lift would force a shape it does not have.

This adds lines rather than removing them — a table is more verbose than the
match arms it replaces. What it removes is the duplication of the law.

Verdicts are unchanged everywhere I can measure: the selftest, an RNA
transcript, argparse.pyc, /bin/ls, git, libc, and mOMonadOS on both the bare
x86_64-unknown-none kernel and the hosted build. Only the self-audit moves, and
only because the binary being audited is this one.
