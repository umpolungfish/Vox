\section{What the driver is}

An HIV gp120 C4 (V3 loop) antibody-escape ``arms race'' pipeline. Given a wild-type epitope and three CDR contact sets, it:

\begin{enumerate}
  \item enumerates every single-amino-acid mutant (the \emph{landscape}),
  \item scores each mutant's \textbf{gap} (escape severity 2/3/4) using a \textbf{glyph-routed rule engine} --- the 12-primitive Shavian glyph table (Red-Hot Rebis / SNS\_PRIME), not a physicochemical proxy,
  \item flags escape threats (gap $\ge 3$, \code{frob=True}),
  \item picks the TOP ESCAPE and renders it with a caret,
  \item judges whether a counter-CDR3 \emph{engages} the CDR3 via 7-bottleneck glyph agreement,
  \item builds vector DNA (CDR3 + linker + counter) and verifies translation round-trip,
  \item measures CDR1/CDR2 coverage of the threat set,
  \item prints \code{FROBENIUS: all checks closed (B4=T)} when its internal asserts hold.
\end{enumerate}

Indexing is 0-based throughout; the kernel's ``position 15'' escape is \code{WT[15] == 'I'}.

\subsection{Glyph algebra (the rule engine)}
Each amino acid carries a 12-tuple
$\langle \vdash \dashv \succ \prec \bowtie \top \in \ni \odot \bot \boxplus \boxdot \rangle$
of Shavian letters (\code{SIDECHAINS}, lines 102--123). Two operations:
\begin{itemize}
  \item \code{glyph_distance(a, b)} --- Euclidean distance on primitive ordinals (\code{PRIM_ORD}).
  \item \code{bottleneck_count(a, b)} --- disagreements on the 7 SNS\_PRIME bottleneck slots ($\succ \prec \top \odot \bot \boxplus \boxdot$).
\end{itemize}

\subsection{Gap models}
\begin{itemize}
  \item \textbf{pinned} (canonical only): position class from the kernel-verified CORE4/TIER3/BASE partition. CORE4 pins \code{{(15,D),(7,E),(21,K),(2,D),(26,R),(18,E)}} get gap 4; other CORE4 get 3; TIER3 gets 3 if the mutant is a charged glyph (D/E/K/R) else 2; BASE gets 2. Histogram \code{{4:6, 3:187, 2:377}} is asserted.
  \item \textbf{auto} (anything else): $n_{\text{contacts}} \ge 2 \rightarrow$ gap 4 iff $d \ge 3.0$ and $b \ge 3$, else 3; $n_{\text{contacts}} = 1 \rightarrow$ gap 3 iff charged-or-$d \ge 2.5$, else 2; $n_{\text{contacts}} = 0 \rightarrow 2$.
\end{itemize}

\section{What the results show}

\textbf{The driver is a checksummed, self-certifying pipeline, and the canonical run is its fixed point.}
Run 01 closes all eight steps with every internal assert holding: the gap histogram \code{{4:6, 3:187, 2:377}} is not just reported but \emph{asserted} equal to \code{CANONICAL_HIST}, the six gap-4 mutants are asserted to be exactly the kernel-verified CORE4 pins, the top escape is asserted to be pos-15 I$\rightarrow$D at gap 4 with the exact mutated sequence, and the coverage is asserted 193/193. The final line \code{FROBENIUS: all checks closed (B4=T)} is therefore not a slogan --- on this run it is backed by six executed assertions. The glyph algebra is doing the scoring: I$\rightarrow$D reads distance 3.4641 with 3 bottleneck disagreements, which is precisely the shape \code{gap_of_auto} would also promote to gap 4 when two or more contacts are present --- the pinned table and the glyph rule agree on the canonical escape, which is the point of the pin.

\textbf{The two gap models are the same algebra read two ways.} Pinned reads the position class from the kernel-verified partition and only the charged-glyph test inside TIER3; auto reads \emph{both} class and severity off the glyph tuple plus the local contact count. Run 04 shows auto recovering most of the pinned shape on its own (135 gap-4 mutants vs 6 pinned --- auto over-assigns gap 4 to high-movement mutants at $\ge 2$ contacts, the pinned table withholds), and run 10 shows the boundary cases of each rule in isolation: CORE4$\rightarrow$4 only for the six pins, TIER3$\rightarrow$3 iff charged, BASE$\rightarrow$2 always; auto$\rightarrow$4 iff $d\ge 3$ and $b\ge 3$ at $\ge 2$ contacts, $\rightarrow$3 iff charged-or-$d\ge 2.5$ at 1 contact, $\rightarrow$2 otherwise.

\textbf{The thresholds are real gates, not formatting.} \code{--top-conf} changes \emph{who is eligible} (run 05: widens eligibility, same winner) and run 19 shows it can even change the \emph{identity} of the winner once gap-4 mutants at conf 0.60 enter the pool (top becomes pos-2 P$\rightarrow$A). \code{--counter-conf} moves the engagement verdict between ``engages'' and ``does NOT engage'' on an unchanged computed conf (runs 01/06), and a non-canonical counter gets a \emph{computed} 7-bottleneck conf (run 07: 0.512).

\textbf{The vector build is an exact codec, not a lookup.} Step [7] assembles CDR3+linker+counter, encodes with the first codon of each residue, and asserts \code{translate(dna) == payload} --- 29 aa $\rightarrow$ 87 nt canonically, 33 aa $\rightarrow$ 99 nt with the custom counter, both round-tripping. The codon-viable count (180/570 canonical, 134/418 custom) is the same machinery on the WT side: a mutant is low-risk iff its residue sits in the single-nucleotide neighbourhood of the max-neighbourhood WT codon (run 10: \code{_neighbors('ATT')} = 8 residues).

\textbf{Every input lane works.} \code{--wt} (01, 02, 17), \code{--wt-file} FASTA with header stripping (08), contact overrides with ranges (03), explicit gap model (04, 19), short sequences through the non-windowed render path (09), and all six validation refusals with clean exit-2 semantics (11--15, empty-WT). \code{--help} documents the full surface (16).

\section{Findings --- where the suite exposes tension}

\begin{enumerate}
  \item \textbf{The default \code{--top-conf 0.80} is canonical-only.} Auto-mode confs top out at 0.60 (gap-4) and \code{0.45+0.001·pos} otherwise, so \emph{every} non-canonical run with default thresholds dies at the eligibility gate (runs 02, 08, 09, 18). The 0.80 value is the special-cased canonical pin; it is not reachable anywhere else. Non-canonical use requires \code{--top-conf $\le$ 0.55}-ish --- the \code{--help} text does not say this.
  \item \textbf{The canonical convention guard (line 395) is gap-mode blind.} It fires on \code{is_canonical and top_conf $\le$ 0.80} and demands the top be exactly \code{(15, 'D', 4)} --- but under auto gaps the top is \code{(15, 'D', 3)} (run 04), \code{(15, 'D', 2)} (run 03), or even \code{(2, 'A', 4)} (run 19). Result: \textbf{canonical WT + auto gap can never complete} --- \code{top_conf $\le$ 0.80} crashes with \code{AssertionError} (exit 1), and \code{top_conf > 0.80} is rejected early (line 310). The one-line fix is to add \code{and gap_mode == 'pinned'} to the guard's condition; as written, \code{--gap-model auto} on the canonical WT is a dead end.
  \item \textbf{Coverage 100\% under auto is by construction, not by measurement.} \code{autodetect_contacts} puts every even position in CDR1 and every odd in CDR2, so CDR1$\cup$CDR2 is the whole epitope and step [8] cannot report below 100\% for autodetected inputs (runs 09, 17). It is only informative on canonical (193/193, where the contacts are real) or explicit-override inputs.
  \item \textbf{stderr/stdout interleave is an artifact, not a bug.} In runs 02/08/09 the error line appears \emph{before} the pipeline header in captured output; the gate at line 383 executes after steps [1]--[4] --- unbuffered stderr simply overtakes buffered stdout under \code{2>\&1}.
\end{enumerate}

\section{Bugs found \& fixed}

Two real defects in the shipped driver; both fixed in place (pre-fix copy: \code{hrace_driver.py.bak_fix}). No behavior change on any previously working input --- the canonical default run is byte-identical to the pre-fix transcript.

\subsection{Convention guard was gap-mode blind (crash, exit 1)}
The post-pipeline guard
\begin{lstlisting}
if is_canonical and args.top_conf <= CANONICAL_TOP_CONF:
    assert (top['pos'], top['new'], top['gap']) == (15, 'D', 4), top
\end{lstlisting}
assumed the canonical pinned outcome under \emph{any} configuration. With \code{--gap-model auto} (runs 04, 19) or a contact override forcing auto (run 03) the legitimate auto-mode winner differs, so the driver printed a correct TOP ESCAPE and then died on its own assert. Fix: the guard now fires only under the model it encodes ---
\begin{lstlisting}
if gap_mode == 'pinned' and is_canonical and top_conf <= CANONICAL_TOP_CONF:
\end{lstlisting}
The pinned-mode pinned assert (histogram, pins, winner, mut\_seq, coverage 193) still executes on every canonical pinned run; it is simply no longer applied to a model it does not describe.

\subsection{Default \code{--top-conf 0.80} was unreachable off the canonical special case}
Confidence is 0.80 only for the canonical (15, D) pair; the gap-4 tier is 0.60 and everything else \code{0.45 + 0.001*pos}. With the hard default 0.80, every non-canonical or auto run (runs 02, 08, 09, 18) exited 2 before finishing --- the default made the tool's own auto mode unusable out of the box. Fix: \code{--top-conf} now defaults to \code{None} and resolves after the gap mode is known:
\begin{lstlisting}
top_conf = args.top_conf if args.top_conf is not None else (
    CANONICAL_TOP_CONF if gap_mode == 'pinned' else 0.60)
\end{lstlisting}
Canonical pinned runs still default to 0.80; auto runs default to the gap-4 tier (0.60), which is the highest tier the auto gate can award by construction. The early reject (line 313) and the eligibility gate (line 384) now use the resolved value, and the early reject applies only in pinned mode --- a canonical auto run with \code{--top-conf 0.95} now reports a clean typed exit 2 from the eligibility gate instead of skipping the whole pipeline.

\begin{notebox}
\textbf{What the fixes show.} The driver's convention asserts were written \emph{as} the canonical pinned derivation --- correct, but they were being enforced on inputs the derivation does not cover. Pinning each assertion to the model it encodes (\code{gap_mode == 'pinned'}) and resolving the threshold default per model is the minimal change that keeps every previously green run byte-identical while making the auto mode reachable by default. The 100\% auto-mode coverage figure (run 02: 382/382) is, as noted in \S6, a by-construction artifact of \code{autodetect_contacts} and is unaffected by these fixes.
